# FAQ

### 这和 GEPA 是什么关系？

GEPA 是优化器，负责“产生候选”；本项目是发布治理，负责“判断候选配不配发布、如何发布、如何回滚”。R1 的候选由 GEPA 产生，本项目不占有该增益；本项目的贡献是门禁、凭证与事务发布，以及把它们做成可复核的开源包。

### 为什么 R1 提升 13.33pp 仍不能发布？

因为发布门禁还看成本比：R1 的推理成本从 ¥0.159 涨到 ¥0.262，比值 1.6477，超过 1.2 的上限。`screen` 档放行（上限 2.0），`release` 档只以这一条理由否决。这正是“值得继续实验”与“可以发布”分离的意义。

### 为什么 R1 不叫“统计显著”？

30 题里只有 4 个不一致对，精确 McNemar p=0.125；配对区间虽然下界 +3.33pp，但区间宽度约 23pp。样本太小，只能作为初步证据。

### R2 是不是“失败”？

是负面结果，不是事故。项目把它完整保留：EM −6.67pp、回归 2/23。它证明“人工改进不一定更好”，也用于检验门禁是否会把真实退化拦下（回放结果：两个档位都否决）。

### 为什么只有 30 题？

受预算与时间限制（R1 整轮约 ¥10、842 秒；R2 约 ¥2.19、1,880 秒）。30 题足够暴露方向性错误，但不足以支撑普适结论。扩大样本是 roadmap 的第一项。

### 早期材料里那组“大样本实测”成绩还有吗？

没有。那是合成脚本产物（占位题 + 预设正确性），不是模型实测，已从本仓库全部删除，包括 README、文档、代码注释与校园应用的接口字段。仓库里不存在任何合成预测结果，本文件也不再复述其具体数字。

### 门禁阈值凭什么定 2pp / 1pp / 5% / 1.2？

`release` 沿用原型的历史默认值，`screen` 是放宽版本。阈值的来源是工程约定而非理论最优；它们可以被覆盖（覆盖后 `profile` 记为 `custom`）。真正的原则是：**阈值必须冻结在候选注册时**，不能看完结果再改。

### 为什么成本比在 R2 里用延迟？

R2 的汇总没有按测试阶段拆分费用，只有整轮金额与每题平均延迟。用延迟作代理并在证据文件里标注 `per_task_latency_proxy`，比编一个费用数字诚实。

### 凭证能防篡改吗？

能防**单点**篡改与断链：改任何字段都要重算哈希，而重算会破坏下一条的 `prev_receipt_hash`。不能防“整链重建”，也不提供身份认证。详见 [decision-receipt.md](decision-receipt.md)。

### 在线闭环是真的调用模型吗？

代码是：`OnlineExecutor` + `OpenAICompatibleRunner` 会真的发 HTTP 请求、按 usage 计费、把调用写进账本。但本仓库的验证只到**本地 mock 端点**（`tests/test_online_runner.py` 起 `http.server`）。没有在评审环境用真实供应商跑过大样本，也没有“真实模型下 EM 提升”的证据。

### `evolve` 会不会偷看测试集？

不会。`evolve()` 的所有候选都用 `val_task_ids` 冻结 GateSpec；测试集只在循环结束后对基线与最终版本各跑一次，结果写在 `test_metrics` 且 `selection_used_test=false`。测试里也断言了候选的 `validation_config.task_ids` 只含验证集。

### 中断后能续跑吗？

两层：运行级 `resume_run_id` 会跳过已完成的 `(task_id, repeat)`；演化级 `engine.resume(run_id, proposer, runner)` 从已提交轮次继续。**只能恢复到轮次边界**，一轮中间被杀需要人工清理。

### 我能用到自己的任务上吗？

可以。`evaluate_gate` 只依赖 `delta_em`、`delta_f1`、`regression_rate`、`cost_ratio`、`interval` 五个字段；评价器可以替换（`EVALUATOR_IDS` 是白名单，需要扩展时在 `contracts.py` 注册）。校园示例演示了另一种评价协议如何复用同一套发布路径。

### 为什么必须先装 `./upstream/gepa`？

PyPI 的 `gepa 0.1.4` 缺少 `best_score`，与本仓库内的同版本源码不一致。先装 PyPI 版本会导致 32 passed / 1 failed。

### 校园应用能上线吗？

不能。它是离线确定性演示：合成制度、合成题、`api_calls=0`、没有授权、没有学生试用。它的价值是证明底座可迁移，不是证明问答质量。

### 项目有公开用户或上游 PR 吗？

没有。当前是作品提交时的冻结版本；公开仓库、Issue 模板与上游适配补丁是计划项，不宣称已完成。
